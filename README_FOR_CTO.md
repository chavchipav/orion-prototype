# Орион · публичная сборка

Содержимое этой папки нужно разместить в корне статического хостинга **ya-orion.ru** без изменения структуры.

- `index.html` — вход в единый кабинет; стартовый экран агронома — «Паспорт поля».
- `orion-land-passport.html` — автономный модуль паспорта поля, открываемый из кабинета.
- `assets/` — код и стили кабинета.
- `CNAME` — домен GitHub Pages.
- `VERSION.json` — версия сборки.

Проверка после публикации:

1. Открыть https://ya-orion.ru/ и войти под ролью «Агроном».
2. Убедиться, что сразу открыт «Паспорт поля».
3. Переключить Воронеж-1 → Ставрополь-1 → Краснодар-1.
4. Проверить слои, годы 2017–2026, севооборот, соседей, экономику и полноэкранный снимок.
5. Убедиться, что URL https://ya-orion.ru/orion-land-passport.html открывается напрямую.

Сборка не содержит исходных кадастровых номеров, точных координат и исходных названий пяти полей.

## Порядок обновления

1. Сохранить предыдущую опубликованную сборку для отката.
2. Развернуть архив в отдельном каталоге и проверить, что index.html и assets находятся на одном уровне.
3. Проверить новую сборку, затем переключить сайт на неё целиком. Не смешивать assets разных версий.
4. Включить HTTPS и сжатие gzip/brotli. HTML и VERSION.json отдавать с Cache-Control: no-cache; хешированные assets — с длительным кэшем.
5. Проверить обновление страницы, скачивание JSON сессии и отсутствие ошибок загрузки ресурсов. При сбое вернуть предыдущую сборку.

## Сценарии и ограничения

- USER_SCENARIOS.md — инструкция для ведущего демонстрации. Технический статус: SCENARIO_AND_STATUS.md. Ссылка на ORION_SEASON_DEMO.md в пользовательской инструкции соответствует SCENARIO_AND_STATUS.md в этом архиве.
- Пройти план сезона → демосессию → обследование → сравнение технологий → закупку → работу → уборку → покупателя. Отдельно: Семеновод → Поиск клиентов → CRM.
- Это статическая демонстрационная сборка, не многопользовательская серверная система. Роли не обеспечивают разграничение доступа; записи хранятся в браузере. Существующий localStorage пользователей не очищать.
- API лаборатории не требуется и не подключён; синтетические результаты обозначены как демо. Географическая подложка поиска клиентов требует интернета.
- node_modules, исходники и ключи для публикации не нужны. CNAME применим к GitHub Pages; на другом хостинге настроить домен средствами хостинга.
- Локальная проверка из распакованного каталога: python3 -m http.server 4186 --bind 127.0.0.1, затем http://127.0.0.1:4186/.
