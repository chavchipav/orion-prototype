# Орион: инструкция по прохождению сценариев

Для ведущего демонстрации и команды продукта. Версия: 6 сентября 2026 года.

Документ описывает действия в текущем продукте, а не техническое задание на будущие функции. Названия элементов сверены с исходным кодом и существующим сценарием показа. Перед встречей нужен контрольный проход на компьютере ведущего.

## 1. Подготовка

1. Открыть [локальный продукт](http://127.0.0.1:4186/). Этот адрес работает только на компьютере с запущенной сборкой. Для удалённого участника нужен опубликованный продукт или пакет от СТО.
2. Выбрать «Агроном» → «Открыть кабинет». Если появился тур — «Пропустить».
3. В паспорте выбрать «Воронеж-1». Для всей демонстрации использовать одно поле.
4. Открыть «План сезона», выбрать год уборки **2027**, нажать «Открыть демосессию».
5. Проверить индикатор **«Демосессия · синтетические результаты»**. Выбрать объект планирования до утверждения плана: весь контур либо один мини-участок.
6. Если здесь уже есть нужные записи, сначала нажать «Выгрузить сессию». Для чистого показа можно затем сбросить только текущую демосессию. Не очищать хранилище браузера целиком.

Данные сохраняются в этом браузере. Они разделены по полю, году и режиму. Выгрузка JSON нужна для резервной копии и переноса; это не серверная синхронизация.

### Маршрут встречи на 35–40 минут

| Время | Сценарий | Что показать как результат |
| --- | --- | --- |
| 5 минут | Изучение поля | Снимок, выбранный участок, история, ограничения данных |
| 7 минут | Обследование и почва | Точки, пробы, результаты, профиль |
| 6 минут | Сравнение технологий | Изменение сценарного урожая и экономики |
| 7 минут | План сезона и закупка | Объёмы ресурсов, бюджет, выбранный поставщик |
| 5 минут | Выполнение и продажа | Задача, уборка, заявка покупателю |
| 3 минуты | Оценка покупки | Цена земли, вложения, сезонная экономика |
| 4 минуты | Кабинет семеновода | Поиск клиента → карточка → CRM |

Короткий маршрут на 15 минут: паспорт → сравнение технологий → применить вариант → план сезона → поставщик → уборка → покупатель. Научные детали и отдельный кабинет семеновода оставить для вопросов.

## 2. Изучить поле перед покупкой или началом сезона

**Вход:** «Паспорт поля» → «Поле и слои».

1. Выбрать поле, год и месяц с доступным снимком. Для подготовленного показа начать с октября 2025 года; если в выбранном поле снимка нет, выбрать доступный месяц.
2. Показать контур и нажать на мини-участок. Сопоставить его номер с выбранным объектом и данными справа.
3. Переключить снимок, NDVI, высоту, уклон и «Застой / низины».
4. В погодном блоке прочитать показатели того же месяца: температуру, осадки, ветер, сухой период и доступные экстремумы.
5. Открыть «Севооборот», переключить год и месяц; сопоставить снимок, NDVI и гипотезу культуры.
6. Открыть «Соседи» и показать доступные объекты окружения и сведения о них.

**Результат:** участник понимает, какой объект изучает, за какой период видит данные и какие зоны требуют внимания.

**Что объяснить:** низина — место потенциального накопления воды, а не доказанное заболачивание. NDVI — отклик растительности, а не урожайность. Гипотеза культуры не заменяет журнал посевов. Серый месяц означает отсутствие данных выбранного слоя, а не отсутствие растительности.

**Не обещать:** юридическое подтверждение всех границ, распознавание культуры по каждому снимку, установленную причину повреждения или дату уборки по одному индексу.

## 3. Спланировать обследование и посмотреть результаты

**Вход:** «Почва и моделирование» → «Обследование», в демосессии.

1. Проверить поле, сезон и объект планирования.
2. Выбрать число точек, глубину и предикторы. Для короткого показа достаточно небольшого набора, например 6 точек на глубине 20 см, если эти значения доступны в контролах.
3. Нажать «Добавить раунд обследования».
4. Выбрать точку на карте и переместить её внутри рабочего контура. Попытка размещения вне объекта должна быть отклонена.
5. Показать карточку пробы: идентификатор, глубину, статус, показатели, единицы и методы.
6. Нажать «Заполнить деморезультаты». Показать появившиеся результаты и выбрать показатель для окраски карты.
7. Добавить второй раунд, если нужно показать повторное обследование. Сравнивать одинаковые методы и глубины.
8. Нажать «Выгрузить точки» и «Выгрузить ведомость» — получить GeoJSON и CSV.
9. Для передачи задачи исполнителю нажать «Запросить обследование лаборатории», выбрать лабораторию для созданной заявки.

**Результат:** план точек, карточки проб, демонстрационные результаты и заявка на обследование.

**Что объяснить:** точки рассчитываются локально, не через Pointer. Значения синтетические. Окраска по ближайшей пробе не является валидированной научной интерполяцией. Выбор лаборатории сохраняет заявку внутри продукта, но не отправляет её лаборатории.

Импорт результатов JSON показывать только с заранее подготовленным совместимым файлом. Не загружать произвольный лабораторный PDF как структурированные измерения.

## 4. Показать развитие растений, почву и датчики

**Вход:** «Почва и моделирование» → «Цифровой двойник».

1. Выбрать сценарий. Перейти ползунком на начало, середину и конец сезона.
2. Показать фазу, биомассу, глубину корней и сценарный урожай.
3. Вращать модель; переключить поверхность и почвенный разрез.
4. Включить и скрыть горизонты 0–40, 40–80 и 80–120 см. Выбрать глубину 20/40/60/100 см.
5. Нажать «Воспроизвести сезон», затем «Пауза». Сопоставить дату, сцену, график и числовые показатели.
6. Открыть «Датчики». Выбрать глубину, показать влажность, температуру и электропроводность.
7. На периоде пропуска показать «Нет передачи» и последнее известное показание. Пропуск не равен нулю.

**Результат:** видна связь даты, почвенного горизонта, состояния растения и временного ряда.

**Что объяснить:** это модельный фрагмент, не фотография поля. Сцена процедурная; научный API лаборатории не подключён. Показания S-01 демонстрационные, её перемещение пока не меняет физику расчёта. При недоступном WebGL использовать резервный разрез и графики.

## 5. Сравнить технологии и выбрать вариант сезона

**Вход:** «Почва и моделирование» → сравнение сценариев либо «План сезона» → «Сравнить технологии».

1. Оставить один вариант базовым и переименовать остальные так, чтобы различия были понятны.
2. Для наглядного сравнения сначала оставить одинаковые культуру, сорт и дату посева.
3. Во втором варианте изменить погоду на «Засушливая». Показать изменение урожая и финансового результата.
4. В третьем изменить один управляемый параметр — например полив или питание. Сопоставить дополнительные затраты и результат. Не менять сразу все параметры: будет непонятна причина разницы.
5. У выбранного варианта нажать «Применить к демоплану».
6. В предварительном просмотре прочитать изменение урожайности и затрат; подтвердить применение второй кнопкой «Применить к демоплану».
7. Перейти в «План сезона» и проверить обновившиеся значения.

**Результат:** один выбранный сценарий связан с ресурсами, работами и экономикой сезона.

**Что объяснить:** расчёт воспроизводимый, но иллюстративный и не калиброванный на поле. Прибавка от полива или питания не является доказанной рекомендацией. Уже выполненные работы сохраняются; существующие условия сделок после изменения плана нужно пересмотреть отдельно.

## 6. Рассчитать семена, материалы, работы и экономику

**Вход:** «План сезона».

1. В «Посев и результат» проверить культуру, площадь, урожайность, цену реализации и потери товарного объёма.
2. В «Потребность в материалах» разобрать одну строку семян: единицу, норму на гектар, долю площади, число применений, запас, размер упаковки, складской остаток и цену.
3. Изменить запас или остаток. Показать разницу между потребностью, количеством упаковок и объёмом закупки.
4. Аналогично проверить удобрения и СЗР. Дозы в демо не выдавать за агрономическое назначение.
5. Проверить список работ, периоды, ответственных и стоимость. Неучтённые расходы добавить отдельно; не считать, что они включены автоматически.
6. Разобрать итог: товарный объём, затраты сезона, деньги на закупки и работы, выручка, операционный результат, безубыточные цена и урожайность.
7. Нажать «Утвердить план». Убедиться, что появилась утверждённая версия.

**Результат:** версия плана с потребностью в ресурсах и рассчитанной экономикой.

**Контроль:** утверждение требует заполненных цен, остатков и урожайности. Неизвестный остаток нельзя заменять нулём без основания. После утверждения или выполнения работ смена объекта ограничена; для другого объекта использовать отдельный сезон. Повторное утверждение неизменённой версии не должно создавать дубли.

**Как читать экономику:** покупка целых упаковок отличается от стоимости потреблённого материала. Валовой объём отличается от товарного после потерь. Операционный результат — не чистая прибыль: налоги, финансирование и неуказанные расходы не включены. Цены вводятся в одной базе, без НДС.

## 7. Найти поставщика и записать переговоры

**Вход:** строка материала → «Подобрать поставщика» → «Компании и сделки».

1. Проверить созданную заявку: материал, объём и направление «Закупка».
2. Отфильтровать каталог по категории, найти компанию.
3. Открыть карточку, показать адрес и опубликованные контакты, если они есть.
4. Нажать «Выбрать для сделки».
5. В сделке заполнить предложенную цену за единицу, сумму, условия, следующее действие и срок. На встрече использовать явно учебное предложение.
6. Ввести «Учебный разговор: запросить цену и срок поставки» в результат звонка → «Записать контакт».
7. Для ресурсной заявки нажать «Применить цену предложения к плану» и подтвердить. Проверить изменение бюджета.

**Результат:** заявка связана с компанией, предложением и следующим действием; цена при явном подтверждении переносится в план.

Контакты организаций реальные там, где публикация проверена; это не проверка дозвоном. Не совершать звонок и не отправлять письмо во время демо без отдельного решения. Продукт не выполняет автоматический обзвон. Сумма предложения и условия сделки требуют проверки после изменения объёма плана.

## 8. Провести работу, внести уборку и перейти к продаже

**Вход:** «Работы и уборка» той же демосессии.

1. В «Осмотры и наблюдения» записать учебное наблюдение → «Сохранить наблюдение».
2. Нажать «Создать задачу по наблюдению». Проверить новую работу в списке.
3. Указать исполнителя, дату и стоимость; отметить выполнение только как учебную запись.
4. В «Уборка и партия продукции» заполнить убранную площадь, массу, влажность, дату и дополнительные расходы уборки.
5. Например, для демонстрации арифметики: площадь 10 га и масса 35 т дадут 3,5 т/га. Использовать эти значения только если объект не меньше 10 га; это не данные реальной уборки.
6. Нажать «Подобрать покупателя». Без массы и даты переход к заявке потребует заполнения.
7. Выбрать покупателя; проверить направление «Продажа», объём, влажность и условия приёмки. Записать учебный следующий шаг.

**Результат:** наблюдение превратилось в работу; запись уборки — в заявку на продажу.

**Граница версии:** здесь нет полного складского и бухгалтерского учёта, нескольких частичных уборок и всех расчётов зачётного веса. Внесённые расходы работ не равны полной фактической себестоимости. Запись стадии сделки не означает реальное заключение договора или оплату.

## 9. Оценить покупку земли

**Вход:** «Оценка покупки» в том же контексте поля и сезона.

1. Ввести рассматриваемую цену приобретения и дополнительные вложения.
2. Сопоставить их с сезонной экономикой выбранного плана.
3. Отметить доступные проверки документов и незакрытые вопросы.
4. Сформировать и выгрузить заключение доступным действием экрана.

**Результат:** структурированное основание для дальнейшей проверки покупки, а не автоматическое решение «покупать».

При использовании демоплана заключение также демонстрационное. Не представлять его как рыночную оценку, юридическую экспертизу или доказательство будущей доходности.

## 10. Отдельный сценарий: семеновод ищет клиентов

**Вход:** переключить кабинет на «Семеновод» → «Поиск клиентов».

1. Показать карту с географической подложкой и шесть объектов демонстрационного набора.
2. Выбрать номер на карте. Сопоставить его со списком и карточкой хозяйства.
3. Отфильтровать регион или найти хозяйство по названию.
4. В карточке разобрать историю посева, площадь, условную потребность в семенах и следующий шаг проверки.
5. Нажать «Добавить в CRM для проверки» → «Открыть клиентов и сделки».
6. Убедиться, что хозяйство появилось в CRM. Повторно не добавлять тот же объект.

**Результат:** кандидат на проверку передан из поиска в продажи.

Метки — демонстрационные места, не границы выявленных спутником полей. Потребность не равна подтверждённому спросу; посев культуры не подтверждает интерес к покупке. Подложке нужен интернет. Если она не загрузилась, использовать список и повторить загрузку карты.

Этот кабинет и сделки сезона агронома пока не образуют единую сквозную базу CRM. Показывать их как два отдельных пути, а не обещать автоматическую передачу сделки между ролями.

## 11. Завершение и восстановление

1. Вернуться к демосессии агронома. Проверить поле и год.
2. Нажать «Выгрузить сессию» и сохранить JSON.
3. Нажать «Вернуться к данным поля»: синтетические пробы и прогнозы не должны подмешиваться в пользовательский план.
4. Для восстановления выбрать исходные поле, год и режим → «Восстановить» → JSON → подтвердить замену текущей сессии.

Не использовать «Сбросить демо» как способ навигации. Это удаление текущей демосессии, поэтому сначала сохранить нужные результаты.

## 12. Контрольный лист перед встречей

- [ ] Локальный адрес открывается на компьютере ведущего; при внешнем показе проверен опубликованный адрес.
- [ ] Выбранное поле, сезон 2027 и деморежим сохраняются при переходах.
- [ ] Есть доступный снимок; месяцы без данных не используются как основной пример.
- [ ] Погодные карточки и подписи читаются на проекторе.
- [ ] Точки создаются внутри объекта; ведомость скачивается.
- [ ] Сцена вращается; при проблемах WebGL доступен разрез.
- [ ] Изменение сценария отражается в плане после подтверждения.
- [ ] План утверждается; поставщик выбирается; цена переносится.
- [ ] Наблюдение создаёт задачу; масса и дата уборки позволяют создать заявку покупателю.
- [ ] Поиск клиентов связывает карту, список и CRM.
- [ ] JSON сессии сохранён; реальные контакты не используются для непреднамеренной коммуникации.

## 13. Если что-то не получилось

| Симптом | Действие |
| --- | --- |
| Локальный адрес не открывается | Проверить запуск сервера на компьютере ведущего. Адрес 127.0.0.1 другого компьютера не ведёт к этой сборке. |
| После обновления виден старый интерфейс | Перезагрузить страницу с обновлением ресурсов; не очищать пользовательские записи без выгрузки. |
| План не утверждается | Заполнить урожайность, цены и остатки; прочитать сообщение рядом с действием. |
| Не меняется объект планирования | Проверить наличие утверждения/выполненных работ; выбрать другой сезон, не удалять выполненное. |
| Результаты исчезли при переходе | Сверить поле, год и деморежим: это разные наборы записей. |
| JSON не восстанавливается | Выбрать те же поле, год и режим; использовать выгрузку совместимой версии, а не произвольный JSON. |
| Нет погоды, снимка или подтверждения события | Выбрать период с данными либо показать пропуск как ограничение. Не подставлять нули. |
| Сценарий изменился, а предложение поставщика осталось прежним | Пересмотреть условия сделки отдельно: автоматическое изменение договорённостей не выполняется. |
